# Header 优化设计

## 目标

在保留当前 Payload Header 内容、导航数据和已完成业务菜单的前提下，将 Header 优化为可上线使用的品牌导航体验。优化覆盖桌面导航排列、一级菜单指示线、滚动态半透明背景、产品分类与卡片表现、链接组、Card Group，以及移动端全宽手风琴导航。

## 范围与边界

- 保留现有 Header Global、导航 block 类型和内容数据，不新增 Payload schema。
- 仅调整 Header 的前端交互、展示结构和局部样式。
- 桌面与移动端继续使用各自现有渲染入口，避免重构已稳定的数据适配层。
- 现有菜单链接、卡片图片、CTA 和分类顺序保持不变。

## 设计

### 桌面一级导航

DesktopNav 将一级导航放在可裁切的外层中，内部轨道保持单行、固定间距和 `white-space: nowrap`。菜单空间不足时，轨道横向滚动，左右箭头根据可滚动状态显示；滚动条隐藏。共享 indicator 绝对定位在 Header 底部，跟随 hover/focus 菜单项的 left 与 width 连续移动，离开后延迟收回。

### Header 与下拉面板

Header 顶部使用不透明白色，页面滚动超过约 30px 后切换为约 60% 白色并启用 30px backdrop blur。下拉面板使用约 70% 白色与相同 blur。背景状态过渡约 300ms；文字、图标和 Logo 不使用整体 opacity。

### Category、Card 与 Card Group

Category tabs 使用整行浅灰圆角背景表示 hover 和 selected，移除箭头、边框和下划线。分类 CTA 位于分类导航底部，产品网格 CTA 位于网格右上角并使用按钮样式。产品卡片使用固定图片区域和固定标题高度，图片仅在容器内轻微放大。Card Group 保持居中最大宽度、较大的列间距、圆角和底部渐变遮罩，移除右下角箭头，CTA 统一放在右上角。

### Link Group

链接使用较小字号和常规字重，收紧纵向间距并保持左对齐。默认无背景和边框，hover 时显示下划线。

### 移动端导航

MobileNav 使用 Header 下方的全宽白色覆盖面板，占据剩余视口高度并内部滚动。一级栏目纵向排列并以分割线分组；有子内容的项目只负责展开/收起，查看全部链接放入展开内容；无子内容的链接保留固定右箭头。手风琴切换使用约 200ms 的高度与透明度动画，箭头约 300ms 旋转，汉堡图标约 300ms 变形。

## 状态与验证

- 桌面宽屏：导航保持一行，一级菜单可正常 hover，indicator 对齐菜单项。
- 桌面窄屏：导航不换行、不缩小字体，箭头控制横向滚动，外层不被撑破。
- 下拉菜单：背景透明度、模糊、分类切换、产品卡片两行布局和 CTA 位置正确。
- 移动端：面板全宽，栏目单独展开，内容过多时面板内部滚动，关闭后页面滚动状态恢复。
- 使用现有 lint、TypeScript、Header 集成测试和 Playwright 浏览器检查验证。

## 风险控制

所有变更限定在 Header 前端组件和 CSS；若实际内容图片比例或既有数据导致视觉异常，先记录并报告，不擅自修改 Header 内容数据。
