## Installed API mismatches and implementation choices

- Public `EmailAdapter` is exported by this canary as `PayloadEmailAdapter`; implementation uses
  that installed public alias. No private Payload internals are used.
- Form-builder emails are already enabled by the installed plugin; its actual afterChange hook
  calls `payload.sendEmail`. Forgot-password calls `payload.email.sendEmail` directly and ignores
  its return result. Both go through the configured adapter. Existing app config lacked serverURL;
  it now uses the canonical server origin so reset/Admin links are correct.
- Native Payload email validation rejects the approved `noreply@localhost` Mailpit example.
  The sender field uses text with shared server validation that explicitly accepts localhost.
- SMTP parsing is a lazy optional parser in env.ts, not a startup parser invocation, so an invalid
  override is a runtime invalid status rather than a fatal startup dependency.
- Extra Compose forwarding is required for the documented env recovery path to reach the container.
- Raw SMTP error messages may contain credentials or message content. Responses/logs use known
  error categories plus safe response codes instead; this deliberately limits detail to prevent leaks.
- No material scope deviation: no history collection, confirmation emails, template editor or queue.
